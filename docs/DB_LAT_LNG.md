# คอลัมน์ `latitude` / `longitude` ในตารางร้านอาหาร (Task32 / U8)

เพิ่มพิกัดให้แต่ละร้านใน `shops[]` ของ `server/data/database.json` เพื่อใช้แสดงร้านใกล้เคียง (U8)

## โครงสร้าง

| คอลัมน์ | ชนิดข้อมูล | Null | ช่วงค่าที่ยอมรับ | คำอธิบาย |
|---|---|---|---|---|
| `latitude` | number (ทศนิยม) | ได้ | -90 ถึง 90 | ละติจูด (WGS84) |
| `longitude` | number (ทศนิยม) | ได้ | -180 ถึง 180 | ลองจิจูด (WGS84) |

กฎ:
- ต้องมีค่าพร้อมกัน หรือเป็น `null` ทั้งคู่ (ห้ามมีค่าเดียว)
- `null` หมายถึง "ร้านยังไม่มีพิกัด" ฝั่งที่ใช้พิกัดต้องรองรับกรณีนี้ (เช่น ข้ามร้านนั้นในการคำนวณระยะ)
- ตรวจโดย `validateCoordinates(latitude, longitude)` ใน `server/controllers/shopController.js` คืน array ข้อความ error (ว่าง = ผ่าน)

ตัวอย่าง:

```json
{ "id": "shop-green-01", "latitude": 14.073359122970857, "longitude": 100.60113944112857 }
{ "id": "shop-green-05", "latitude": null, "longitude": null }
```

## ที่มาของพิกัด

คัดลอกด้วยมือจาก Google Maps (คลิกขวาที่ตำแหน่งโรงอาหาร) เมื่อ 14 พ.ย. 2569
เป็นพิกัดของ **โรงอาหาร** ไม่ใช่ของแต่ละล็อค ร้านในโรงอาหารเดียวกันจึงใช้พิกัดเดียวกัน

| โรงอาหาร | latitude | longitude | ร้าน |
|---|---|---|---|
| กรีนแคนทีน (`green`) | 14.073359122970857 | 100.60113944112857 | shop-green-01 ถึง 04 |
| โรงอาหารคณะวิทยาศาสตร์ (`sci`) | 14.07259451627268 | 100.60859730370368 | shop-sci-01 ถึง 04 |

## ร้านที่เป็น `null` (ข้อมูลทดสอบ)

`shop-green-05` และ `shop-sci-05` ตั้งเป็น `null` ทั้งคู่ เพื่อให้ Task35 ทดสอบกรณีร้านไม่มีพิกัด
ไม่ได้หมายความว่าร้านเหล่านี้ไม่มีที่ตั้งจริง

## ผลต่อ API เดิม

`GET /api/shops` และ `GET /api/shops/:id` ส่ง `latitude` และ `longitude` เพิ่มมาใน object ร้านอัตโนมัติ
(ส่งทั้ง shop object) field เดิมไม่เปลี่ยน
