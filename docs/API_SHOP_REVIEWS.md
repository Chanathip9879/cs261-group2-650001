# สเปก API: รีวิวร้านอาหาร (U9 / Task37)

เอกสารนี้กำหนดรูปแบบ API รีวิวที่ฝั่ง Frontend (Task38) เรียกใช้
Frontend ทำเสร็จแล้วตามสเปกนี้ ฝั่ง Backend (Task37) ต้องทำให้ตรงกันจึงจะใช้งานได้

## โครงสร้างรีวิว 1 รายการ

```json
{
  "id": "rv-001",
  "shopId": "shop-green-01",
  "username": "นักศึกษาวิศวะ ปี 2",
  "comment": "ข้าวแกงอร่อย ตักเยอะ คิวไม่นาน",
  "rating": 5,
  "tags": ["คุ้มค่า ให้เยอะ อิ่มท้อง"],
  "createdAt": "2026-11-15T07:30:00.000Z"
}
```

| ฟิลด์ | ชนิดข้อมูล | คำอธิบาย |
|---|---|---|
| `id` | string | รหัสรีวิว (ไม่ซ้ำ) |
| `shopId` | string | FK ไปที่ `shops[].id` |
| `username` | string | ชื่อผู้รีวิว (trim แล้ว) |
| `comment` | string | ข้อความรีวิว (trim แล้ว) |
| `rating` | integer 1-5 | คะแนนดาว (ไม่บังคับ) |
| `tags` | string[] | แท็กจุดเด่นที่ผู้ใช้เลือก (ไม่บังคับ) |
| `createdAt` | string (ISO 8601) | เวลาที่เขียน (Server เป็นผู้กำหนด) |

## 1. ดึงรายการรีวิว

`GET /api/shops/:id/reviews` (ไม่ต้อง Login)

```json
200 { "success": true, "data": [ /* รีวิว เรียงใหม่สุดก่อน */ ] }
404 { "success": false, "message": "ไม่พบร้านอาหาร" }
```

ร้านที่ยังไม่มีรีวิว ให้ส่ง `data: []` (Frontend จะแสดง "ยังไม่มีรีวิว")

## 2. เขียนรีวิว

`POST /api/shops/:id/reviews` (ไม่ต้อง Login)

Request body:
```json
{ "username": "นักศึกษาวิศวะ ปี 2", "comment": "ข้าวแกงอร่อย ตักเยอะ คิวไม่นาน", "rating": 5, "tags": ["คุ้มค่า ให้เยอะ อิ่มท้อง"] }
```

`rating` และ `tags` ไม่บังคับ (Frontend ส่งมาเมื่อผู้ใช้เลือกในหน้าเขียนรีวิว)

| สถานะ | Response |
|---|---|
| สำเร็จ | `201 { "success": true, "data": { /* รีวิวที่บันทึกแล้ว */ }, "message": "..." }` |
| ข้อมูลไม่ผ่าน | `400 { "success": false, "message": "...", "errors": { "username": "...", "comment": "..." } }` |
| ส่งถี่เกินไป (กันสแปม) | `429 { "success": false, "message": "..." }` |
| ไม่พบร้าน | `404 { "success": false, "message": "ไม่พบร้านอาหาร" }` |

- ต้องส่ง `data` เป็นรีวิวที่บันทึกแล้ว (มี `id` และ `createdAt`) Frontend จะแสดงรีวิวใหม่บนสุดทันทีโดยไม่โหลดรายการใหม่
- `errors` ใส่เฉพาะช่องที่ผิด Frontend จะแสดงข้อความใต้ช่องนั้นโดยไม่ล้างข้อความที่ผู้ใช้พิมพ์ไว้

## กฎตรวจข้อมูล (ต้องตรวจซ้ำที่ Backend)

ตรวจหลัง trim ช่องว่างหน้า-หลังแล้ว (ค่าเดียวกับ `client/src/utils/reviewValidation.js`)

| ช่อง | กฎ |
|---|---|
| `username` | ห้ามว่าง, ไม่เกิน 30 ตัวอักษร |
| `comment` | ห้ามว่าง, อย่างน้อย 5 ตัวอักษร, ไม่เกิน 500 ตัวอักษร |
| `rating` | ถ้าส่งมา ต้องเป็นจำนวนเต็ม 1-5 |
| `tags` | ถ้าส่งมา ต้องเป็น array ของ string |

ข้อแนะนำกันสแปม: จำกัดจำนวนรีวิวต่อ IP ต่อร้าน (เช่น 1 รีวิว/นาที) แล้วตอบ `429`

## สิ่งที่ Frontend ทำตาม response

| กรณี | การแสดงผล |
|---|---|
| โหลดรายการสำเร็จ / ว่าง | แสดงรายการ (ชื่อ, ข้อความ, วันที่) / "ยังไม่มีรีวิว" |
| โหลดรายการไม่สำเร็จ | ข้อความแจ้ง + ปุ่ม "ลองใหม่" |
| ส่งสำเร็จ | ล้างฟอร์ม, กลับไปหน้าร้าน แล้วแสดงรีวิวใหม่บนสุด (ไฮไลต์ "รีวิวของคุณ"), แจ้ง "ส่งรีวิวเรียบร้อย" |
| 400 | ข้อความใต้ช่องที่ผิด (ไม่ล้างข้อความที่พิมพ์) |
| 429 / 5xx / เชื่อมต่อไม่ได้ | ข้อความด้านบนฟอร์ม (ไม่ล้างข้อความที่พิมพ์) |

## ไฟล์ Frontend ที่เกี่ยวข้อง

- `client/src/services/api.js`: `getShopReviews()`, `createShopReview()`, `ReviewApiError`
- `client/src/utils/reviewValidation.js`: กฎตรวจข้อมูล และรูปแบบวันที่
- `client/src/pages/WriteReviewPage.jsx`: ฟอร์มเขียนรีวิว (หน้า `#/shop/:id/review`)
- `client/src/components/ReviewList.jsx`: รายการรีวิวในหน้าร้าน
- `client/src/pages/ShopDetailPage.jsx`: หน้าร้านที่แสดงรายการรีวิว
